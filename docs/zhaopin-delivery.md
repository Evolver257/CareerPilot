# 智联招聘一键投递

## 使用

1. 重新加载 `apps/extension/.output/chrome-mv3` 扩展，并刷新 CareerPilot 页面和已有招聘标签页。
2. 在智联招聘登录并确认平台账号中的简历。系统内简历用于匹配，不会在投递时自动上传到智联。
3. 在投递计划中批准岗位，使其进入排队状态。超过采集时间三天的岗位仍需重新采集才能自动投递。
4. 自动化任务 → 选择投递计划 → 一键投递。BOSS 与智联可混合，扩展复用一个后台标签页串行执行。
5. 智联打开原岗位页，校验平台和职位 ID 后点击唯一可用的“立即投递”。只有可见成功提示或已投递按钮才更新为已投递。
6. 遇到登录、验证码、简历选择、失效岗位、未知页面或结果不明确，暂停并查看执行详情。在扩展已打开的同一招聘标签页处理完成后，点击“已处理，继续任务”。不要新开页面重复提交。

## 边界与实现

- 使用既有 BrowserTask / Application 状态机与计划级任务记录，不调用智联私有投递接口。
- 页面按钮点击是实际对外投递操作；前端按钮文案明确本次批准投递的岗位数。
- 任务创建时保持 PENDING；扩展真正连接岗位时启动，启动前再次校验岗位新鲜度。扩展未响应时不谎报成功，重试复用待启动任务。
- 登录/验证由用户处理，不绕过验证码或平台访问限制；不会自动选择额外简历、继续沟通或投递推荐职位。
- 点击前保存同一标签页的 sessionStorage 防重标记。未取得明确结果时重试只核验，不再次点击。该标记不是跨浏览器/关闭标签页后的平台级幂等保证。
- 成功识别包括已投递按钮、可见投递成功通知，以及 `.deliver-greeting-modal__title` 中“已向对方发送简历和打招呼语”。隐藏模板不算证据。
- 暂停通知不向服务器回传 ACTION_RESULT，避免 WAITING_FOR_USER 状态的连接被错误关闭。
- 单标签页投递队列复用既有内存队列：扩展进程重启后的队列自动恢复不在本次新增范围。未启动任务保留，可重新从计划启动；已点击但未确认的岗位应人工核验。

## 验证

本地 DOM、扩展队列和隔离数据库测试覆盖混合平台串行、重复请求、明确成功、隐藏成功弹窗、错岗位、失效按钮、登录/验证暂停、人工继续和状态持久化。智联公开岗位页仅做只读 HTML 核对，没有用真实账号提交申请。网站改版或账号专属确认流程仍需首次实际使用时确认。
